Source and verification notes

Program logic is C, including argument parsing, option processing, the driver,
COMDAT allocation, mapped-file/cache handling, COFF readers, module/library and
section/group lists, object processing, and link-pass orchestration. Functions
remain separate at the original graph boundaries. Source declarations recover
cdecl stack arguments and returns; Win32 callbacks and mapped-file API pointers
use WINAPI. The native compiler expresses the dispatcher's structured exception
handling and the console handler's stdcall ABI. No implementation required an
assembly ABI exception. INT3 in pending stubs is part of the required workflow.

functions.json stores original virtual addresses and known extents, the ordered
accepted history, and the case that exposed each frontier. Source replacement
does not create a new acceptance: affected historical frontiers are replayed.
An entry-only range on a pending stub is not a claim to know its full extent.
Determine that extent when the stub is reached before accepting its C body.
The known extents include original intra-function constants where applicable.

Internal C layouts belong to this reconstruction. ImageOptions models named
settings rather than preserving unused original-layout slots. FileSlot, Page,
Contribution, Module, Library, Section, Group, symbol tables, and enumerators
have contextual types and named fields. Some unreached consumers still need
further semantic recovery. COFF/PE structures and the serialized DOS stub use
the target platform's file-format layouts. The DOS message program is output
file data, described by fields; it is not an execution mechanism for LINK.

Data is defined with its owner. There are no original section snapshots or
anonymous image arrays. Ordinary strings occur at use sites. The two named
ordinary string arrays are sentinels: pass one compares output_name against
coff.out by address, and the CVPACK launcher distinguishes its default program
object by address. Section-default records combine names and flags used by
multiple callers. The dispatch/help tables retain their actual table roles.
The debug-flags array ends at original 0005c06c, where independent Macintosh
state begins; it no longer doubles as storage for unrelated linker globals.

The original LIBC.LIB supplies verified static runtime routines. The matcher
checks COFF bytes and relocation targets, including external calls, and treats
same-address aliases as one vertex. Older CRT differences in the executable
have C equivalents in runtime.c. CRT globals such as _iob, _osfile, locale data,
and heap state use the linked library's named globals. crt-anchors.c requests
the original floating-point/termination members without copying library data.

The graph audit compares calls including indirect calls and tail calls. The
callback audit compares relocated function addresses embedded in each accepted
source routine, including enumerator methods and qsort/CRT callbacks. The data
audit checks named initial values and pointers; pointers to ordinary literals
are compared by string value where address identity is not significant.
These static checks complement execution, rather than proving every future path.
The instruction scanner recognizes switch tables both with scaled indexes and
with an index shifted before JMP [register+table], as emitted by /Od.

External symbols have a COFF symbol record and named owner/value unions for
contributions, reference lists, final values, and undefined-list back links.
Their private C layout omits fields whose consumers have not yet been reached;
COFF records themselves retain the required 18-byte file layout. The weak-symbol
counter is shared by override handling and definition transitions. Hash nodes and
interned-name nodes draw from the retained small-allocation pool; this is mutable
allocator state, not copied executable data. The streaming reader similarly owns
one typed, reusable IMAGE_SYMBOL object.

The /? regression is complete. Minimal-C has advanced through COMDAT roots,
.drectve parsing, default-library registration, contribution relocation scanning,
object-symbol merging, and initial hash lookup/insertion. Subsystem inference,
startup selection, lazy default libraries, path search, and
archive linker-member indexes now have C implementations. The archive code models
member offsets, symbol/member indices, raw names, and a name-pointer index as
separate fields. The file cursor and archive globals are named input_file and
archive_data_offset for their observed roles. The case currently stops at
count_output_sections. Extraction now reads the needed CRT/import members and
updates the undefined list after definitions, while contribution iterators mark
.idata sections. Relocation reachability edges have named, resolved-external,
and contribution fields; linker-defined nodes grow their edge capacity as needed.
Layout and output helpers remain named traps. Do not
claim generated-image equivalence until that case exits and its fixture executable
passes byte comparison and execution. Normalize only the four-byte PE COFF timestamp
specified by each fixture manifest. hello-win32 follows minimal-C and additionally
needs its GUI window/paint/close check from the shared fixture verifier. Fixture
input files must remain untouched.

The import-order checkpoint contains 274 accepted frontiers. Original addresses
1a390, 17a80, 19e50, and 1fe10 now have recovered names reflecting their bodies:
order_import_contributions, apply_order_file, apply_section_merges, and
resolve_local_imports. Earlier provisional labels were replaced before acceptance.
The optional import-library driver uses buffer offsets while its command buffer
can move, then converts them to argv pointers before spawning LIB. Group iteration
follows the live next link while import contributions are spliced within module
runs. As in the original, sorting and splicing leave the cached group tail alone.
Section merging uses a word count distinct from Macintosh metadata. The local
import pass returns a contribution and a list pairing aliases with definitions.
New frontiers 259 through 273 and affected predecessor frontiers have been
replayed with matching traps; help remains exact. Minimal-C still stops before
symbol emission and has no validated generated image.

The symbol-output checkpoint contains 288 accepted frontiers. Full history replay
and exact help pass. External's state union now reflects original offset1c:
undefined-list next pointer before definition, emitted index after output. The
unconsumed original offset20 field remains omitted from our private layout.
Name sorting copies the table's TextBuffer into shared comparator context. Its
two nine-byte short-name buffers are mutable and independently retain the names
for one comparison; their initial eight spaces and terminators match the target.
Hash flags have their observed WORD type. Nested enumeration uses a typed cursor
(bucket, returned count, chain next, previous cursor). No machine assembly or
additional named ordinary literals were introduced. The output writer and
undecoration paths inside emit_externals still have named pending dependencies;
only the reached diagnostics path is dynamically covered so far.
The queued GUI checker branch has been added to compare.py and built using the
original toolchain. The shared captured hello.exe passes its title/paint/close
check, with 300 dark pixels and exit0. This is checker validation, not completion
of the queued reconstructed LINK fixture.
