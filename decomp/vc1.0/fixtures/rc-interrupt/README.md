This immutable case exercises RC 3.10's registered console interrupt handler using a real `GenerateConsoleCtrlEvent(CTRL_C_EVENT, 0)` in a private Wine console. The command is `RC.EXE /x /fointerrupt.res interrupt.rc`; the original RCPP child and inherited original-toolchain environment remain in use.

`capture-interrupt.c` is analysis tooling compiled by the RC Makefile, excluded from the reconstructed RC link. It observes successful native `SetConsoleCtrlHandler` registration and stops the primary thread at `initialize_lexer`, after RCPP completes. At that boundary the directory contains the unchanged source, zero-byte output, prepared RC input and preprocessed RD output. Their raw bytes and actual OS PID names are retained in `evidence/original/before`.

The controller clears its own inherited Ctrl+C-ignore flag before normal child creation. The child inherits its console/group and installs its original handler normally. Membership is checked to contain exactly controller and RC; group zero therefore broadcasts only within this newly allocated console. The controller's harmless handler must receive exactly one Ctrl+C; RC's handler must receive argument zero on a distinct OS-created thread. The debugger passes the real `DBG_CONTROL_C` exception as not handled. No remote thread creation, callback invocation, handler-pointer injection, PID override, target-code replacement or output normalization is used. Temporary observation breakpoints are repaired; preexisting INT3 frontiers are never bypassed.

Wine defers SIGINT dispatch while the primary thread is suspended. After queuing the real event, the helper resumes that thread, then suspends it again at the OS callback-thread creation debug event. The native callback subsequently deletes the open partial output and both temporary files, exits 1 and emits no stdout or stderr. Only the unchanged input remains. Raw successful proof, events, streams, before and after files are recorded; `capture.py` independently repeats and validates the same relations with newly assigned IDs. PID-dependent temporary names and the RD file's literal RC filename are checked against the actual process ID without normalizing captured bytes.

Run `make -C decomp/vc1.0/rc -j2 build/interrupt-run.exe`, then `python3 decomp/vc1.0/fixtures/rc-interrupt/capture.py`. It uses its own `~/.ai-tmp/vc1.0-rc-interrupt/wine` prefix and maps T: to the original toolchain. No host locale/codepage changes are required.

A real targeted CTRL_BREAK experiment is retained separately under `limitations/ctrl-break-wine10`. On Wine 10.0 it exits 1 without entering the registered callback and leaves output and temporaries behind. This is environment-limit evidence, **not reconstruction acceptance**. Wine 10.0 maps CTRL_BREAK to SIGQUIT and Ctrl+C to SIGINT in its [console server](https://github.com/wine-mirror/wine/blob/wine-10.0/server/console.c). Its [i386 signal implementation](https://github.com/wine-mirror/wine/blob/wine-10.0/dlls/ntdll/unix/signal_i386.c) creates the native console dispatcher thread for SIGINT, whereas SIGQUIT aborts a thread. Its [console dispatcher](https://github.com/wine-mirror/wine/blob/wine-10.0/dlls/kernelbase/console.c) raises the debugger control exception and respects inherited ignore-C state. These tagged implementation facts explain choosing real Ctrl+C with inherited group semantics instead of treating a successful CTRL_BREAK API return as proof of callback execution.

The assigned interrupt boundary has no font resource, so the handler's conditional font-directory deletion is recovered from its complete function but that branch is not claimed exercised. No assertion of complete RC branch coverage is made.
