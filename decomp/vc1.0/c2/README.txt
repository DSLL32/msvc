C23232.EXE 1.0-nt reconstruction (project vc1.0)

Current workflow
----------------
Reconstructed Win32 C is in src/; tooling is in scripts/. Run make from this
binary directory. Normal fixtures execute native i386 ELF only, with -O0 -g.
Shared compatibility/tracing C sources in lib/recon are compiled directly at
final link, without an archive or application instrumentation on the shims.

    make -j4 native native-trace    build output-only and traced native targets
    make -j4 check                 cached original application traces + outputs
    make -j4 replay                the same native regression suite
    make hello-frontier            native hello prefix and expected named trap
    make -j4 native-check          native output/status checks without tracing
    make -j4 win32                 explicit original-toolchain compilation
    make -j4 audit                 explicit Win32 ABI/function-graph audit

No fixture invokes Wine, launches an original, or refreshes reference data.
The paired Wine regression runners were removed. Original-toolchain compiler
work and PE graph/extent analysis remain explicit operations outside fixtures.
Toolchains and captured fixtures are read-only; the private reference/compiler
prefix is ~/.ai-tmp/vc1.0-c2/wine, and native scratch lives beside it.

Target: toolchains/1.0-nt/bin/C23232.EXE
SHA256: 0a64eab35cfb4bfb8af452653d21707947ada33952a82a5e712c275ab7712d26
Original image base: 00010000; entry point: 00073470.

Two cases are supported. Minimal-C consumes four captured IR files, exits0,
and produces the exact286-byte test.obj with only COFF timestamp bytes4..7
normalized. Optimized Win32 hello consumes its captured IR and remains
incomplete at is_function_reference27310. No final hello object is
claimed. Both cases have no source-file input and no additional argv. Their
MSC_CMD_FLAGS options retain relative -il ir and the original metadata paths.
All input/manifest/reference hashes and empty output streams are checked.

cases/native-traces.json projects existing independent original histories onto
977 audited application definitions. The five reconstructed CRT overrides in
src/runtime.c, other CRT/imports and shared shims are excluded on both sides.
Minimal expects270 application first entries and exit0. Hello seeds those270
seen entries, expects379 accepted new application entries plus the named still-stubbed
next-function canonicalization entry, and requires SIGTRAP. Each process uses a fresh shared seen
bitmap; unexpected process invocations are rejected by the fixture broker.
The projection cache is never regenerated by normal checks. Initial --write
bootstraps from historical captures. After a new acceptance, an explicit offline
`python3 scripts/native-traces.py --extend-before BEFORE --extend-after AFTER`
validates fresh original-only receipts before appending exactly one entry.
The current before/after receipts are stored in cases/hello-pentium-reference-
before.json and hello-pentium-reference-after.json; the trial receipt records
the670-entry baseline cache and exact reproduction command.
Original capture remains outside fixtures; extension rejects inconsistent trap
addresses, metadata, inputs, environments and application definitions. Missing, changed,
unmapped and ambiguous references/functions fail rather than trigger capture.

All reconstructed C/H include recon.h last in their ordinary include list.
It is empty in canonical Win32 builds. Original calling conventions, CRT32
FILE fields and the two x87/ESI ABI blocks remain intact. Naked application
entries have the shared trace marker because Clang otherwise omits entry
instrumentation there; it is empty outside the native traced build. Binary
stdio defaults match original BINMODE.OBJ via RECON_DEFAULT_FMODE=0x8000.
Only traced application objects use -finstrument-functions. Native builds
preserve the existing named trapping stubs and do not implement another function.

See cases/native-all-validation.json for fixture setup/execution/check timing,
cases/native-build-validation.json for measured build/audit timing when present,
and PAUSED.txt for the current reconstruction frontier and remaining WIP.
Timing notes identify unmeasured build, capture and prefix work; fixtures perform
none of those reference operations. Negative checks reject wrong expected
entries and non-clock object corruption. Failure scratch retains invocation,
trace, status, streams and input files for native GDB inspection.
