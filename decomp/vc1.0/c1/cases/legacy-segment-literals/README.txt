Legacy named-base records, counted literals and declarator recovery
=================================================================
One coherent record/callback program runs with actual parsed -m/-Zf/-Jd flags.
Valid revision2 has packed named-base links, far Pascal code callbacks, counted
Pascal literals including concatenation, ordinary escaped bytes and macro/header
conditionals. Both untouched originals exit0 silently and produce exact IR sizes
435/2364/561/107/480 (irdb/irex/irgl/irin/irsy).

Revision3 adds a deliberately invalid relative-scalar annotation. This explicit
expected-error phase emits C2154 plus C4040, exits1 and leaves exact partial IR
11/1244/24/107/5 bytes. Two fresh originals bind its complete streams/artifacts.
It exercises real prefix-copy/check/ignored-model recovery without asserting that
the invalid declaration is supported. The initial expected0 failure is retained.

The two phases add six application functions/414 bytes, preserving original
boundaries and stdcall cleanup. Former placeholder names were misleading:
initialize_japanese_characters becomes disable_multibyte_identifier_bytes
(class42 to invalid23), and append_type_shape becomes merge_type_shape_modifiers
(no related-chain append). No CRT function or shared shim is reconstructed here.
Fresh original first-entry projections and native traces/status/streams/all files
match. No target-global or parser-token state is seeded.

Rejected revision1 attempted __segment, far data pointers and extended-byte
identifiers. Its original exit39 and all raw files remain unchanged. The shipped
keyword table lacks segment/segname/self spellings even though old grammar paths
remain; those handlers have no established public producer and stay unresolved.
The successful revision2 inputs/oracles also stay pinned when revision3 is used.

A rename initially left two old callers, causing a native link failure followed
by an unsuccessful debug launch with no executable. Both are retained; all callers
were corrected before the matching continuation. A case-preparation path-variable
mistake wrote an intended manifest into a temporary v2 copy; the phase lookup then
failed before launching the original. The unchanged v2-case archive restored that
copy byte-exact, checked against frozen hashes. Historical raw evidence was never
changed or relabelled.

Run make -j4 check CASE=legacy-counted-records or CASE=legacy-prefix-diagnostic.
These fixtures are native-only and consume cached references. Evidence consists
of ordinary files with SHA256/size bindings, excluding executable/toolchain/auditor
bundles. validation.json records fixture elapsed accounting and final checks.
